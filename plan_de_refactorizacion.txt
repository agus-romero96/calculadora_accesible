# Plan de Refactorización para Calculadora Accesible

## 1. Introducción

Este documento describe una estrategia para refactorizar el proyecto "Calculadora Accesible", con el objetivo de mejorar la organización del código, facilitar su mantenimiento y permitir que se agreguen nuevas funcionalidades de manera más sencilla.

Los puntos clave son:
- Dividir el archivo monolítico `operations.py` en módulos más pequeños y cohesivos.
- Reestructurar la interfaz de usuario en `ui.py` para reflejar esta nueva organización.
- Rediseñar el sistema de menús para que sea más intuitivo y escalable.

---

## 2. Refactorización del Módulo de Operaciones

El archivo `operations.py` actualmente contiene una única clase `Algebra` con más de 600 líneas de código, mezclando lógica de parsing, cálculo diferencial, álgebra lineal y aritmética básica.

### Propuesta: Estructura de Directorio y Clases

Se propone crear un nuevo directorio `operaciones/` que reemplazará al archivo `operations.py`. Dentro de este directorio, la lógica se dividirá de la siguiente manera:

```
calculadora_accesible/
├── operaciones/
│   ├── __init__.py
│   ├── parser.py         # Lógica para interpretar texto (la función _parsear_seguro)
│   ├── aritmetica.py     # Operaciones básicas y simplificación
│   ├── ecuaciones.py     # Resolución de ecuaciones y factorización
│   ├── algebra_lineal.py # Matrices, determinantes y sistemas de ecuaciones
│   └── calculo.py        # Derivadas, integrales y límites
├── ui.py
├── main.py
└── (otros archivos)
```

### Detalle de Clases y Métodos:

**a) `operaciones/parser.py`**
Contendrá una clase o funciones dedicadas a la interpretación de expresiones.
- **`Parser` class:**
  - `_parsear_seguro(expresion)`: El método actual para convertir texto a un objeto SymPy.
  - Podría extenderse con más lógica de validación en el futuro.

**b) `operaciones/aritmetica.py`**
Clase para operaciones fundamentales.
- **`Aritmetica` class:**
  - `EvaluarExpresion(expresion)`
  - `SimplificarEcuacion(expresion)`

**c) `operaciones/ecuaciones.py`**
Enfocada en resolver ecuaciones y álgebra polinómica.
- **`Ecuaciones` class:**
  - `ResolverEcuacion(ecuacion, variable)`
  - `IntentarFactorizar(expresion)`

**d) `operaciones/algebra_lineal.py`**
Todo lo relacionado con matrices y sistemas.
- **`AlgebraLineal` class:**
  - `Determinante(matriz_str)`
  - `ResolverSistemaPasos(lista_ecuaciones)` (Gauss-Jordan)
  - `ResolverSistemaCramer(lista_ecuaciones)`
  - `ResolverSistemaEducativo2x2(lista_ecuaciones, metodo)`
  - `_matriz_a_texto(matriz)` (Helper privado)

**e) `operaciones/calculo.py`**
Clase para cálculo diferencial e integral.
- **`Calculo` class:**
  - `Derivada(expresion, variable)`
  - `Enecima(expresion, variable, orden)`
  - `Integral(expresion, variable)`
  - `CalcularLimite(expresion, variable, tendencia)`
  - `_detectar_regla_derivada(expr, var)` (Helper privado)
  - `_pasos_a_texto(rule)` (Helper privado)

## 3. Impacto en `ui.py`

La clase `Calculadora` en `ui.py` deberá ser actualizada para usar la nueva estructura.

**Antes:**
```python
from operations import Algebra

class Calculadora(wx.Frame):
    def __init__(self):
        # ...
        self.operaciones = Algebra()
        # ...
    
    def on_evaluate(self, e):
        self.show_res(self.operaciones.EvaluarExpresion(self.get_val()))
```

**Después (Propuesta):**
```python
# Importar todas las nuevas clases
from operaciones.aritmetica import Aritmetica
from operaciones.ecuaciones import Ecuaciones
from operaciones.algebra_lineal import AlgebraLineal
from operaciones.calculo import Calculo

class Calculadora(wx.Frame):
    def __init__(self):
        # ...
        # Instanciar un motor de cálculo para cada categoría
        self.aritmetica_motor = Aritmetica()
        self.ecuaciones_motor = Ecuaciones()
        self.algebra_motor = AlgebraLineal()
        self.calculo_motor = Calculo()
        # ...

    def on_evaluate(self, e):
        # Llamar al método desde el motor correspondiente
        self.show_res(self.aritmetica_motor.EvaluarExpresion(self.get_val()))

    def on_derivar(self, e):
        self.show_res(self.calculo_motor.Derivada(self.get_val()))
```

## 4. Rediseño del Menú

El menú actual es funcional, pero puede organizarse mejor para reflejar la estructura del dominio matemático y dar espacio a futuras funciones.

### Propuesta de Estructura de Menú:

- **&Archivo**
  - Salir (`Alt+F4`)

- **&Básico**
  - Evaluar Expresión (`Enter`)
  - Simplificar Expresión (`Ctrl+S`)
  - Factorizar (`Ctrl+F`)

- **&Álgebra**
  - Resolver Ecuación... (`Ctrl+R`)
  - **Sistemas de Ecuaciones ▸** (Submenú)
    - Resolver con Gauss-Jordan...
    - Resolver con Regla de Cramer...
    - Resolver Sistema 2x2 (Didáctico)...
  - **Matrices ▸** (Submenú)
    - Calcular Determinante... (`Ctrl+M`)
    - (Futuro) Invertir Matriz...
    - (Futuro) Multiplicar Matrices...

- **&Cálculo**
  - Derivar (Simple) (`Ctrl+D`)
  - Derivar (Orden N)... (`Ctrl+Shift+D`)
  - Integrar (Indefinida) (`Ctrl+I`)
  - Calcular Límite... (`Ctrl+L`)

- **A&yuda**
  - Guía de Símbolos y Sintaxis (`F1`)
  - Acerca de...

Esta estructura con submenús (`▸`) mantiene la barra de menú limpia y agrupa lógicamente las operaciones relacionadas, haciendo la aplicación más fácil de navegar.

---

## 5. Pasos para la Implementación

1.  **Crear el directorio `operaciones/`** y el archivo `operaciones/__init__.py`.
2.  **Crear `operaciones/parser.py`**: Mover la función `_parsear_seguro` y sus dependencias de `sympy.parsing`.
3.  **Crear los demás archivos de operaciones**: `aritmetica.py`, `calculo.py`, etc.
4.  **Mover los métodos**: Cortar y pegar los métodos de la clase `Algebra` original a las nuevas clases correspondientes. Asegurarse de que cada clase importe lo que necesita (ej: el `parser`).
5.  **Actualizar `ui.py`**: Cambiar los `import` y la inicialización de `self.operaciones` por los nuevos motores de cálculo.
6.  **Modificar los manejadores de eventos**: Actualizar los métodos `on_...` para que llamen a los motores correctos (ej: `self.calculo_motor.Derivada(...)`).
7.  **Rediseñar el menú**: Modificar el método `init_menu` en `ui.py` para crear los submenús propuestos.
8.  **Probar exhaustivamente**: Verificar que cada función del menú siga funcionando como se espera.
9.  **Eliminar `operations.py`**: Una vez que todo funcione, eliminar el archivo antiguo.
